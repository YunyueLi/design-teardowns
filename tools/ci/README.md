# 检查与发布规则

`scope.mjs` 同时决定 PR 和 main 的检查范围。分流规则、工作流结构和结果复用逻辑均由 `npm test --prefix tools/ci` 验证，工作流语法由固定版本且核对 SHA-256 的 actionlint 检查。

| 改动 | PR 检查 | main 发布 |
| --- | --- | --- |
| `.github/`、`tools/ci/`、明确列出的工程文档 | 轻量策略和工作流检查 | 跳过 |
| `tools/` 下的测试、生成器、浏览器依赖 | 策略、目录维护、完整浏览器验收 | 跳过 |
| 网站、馆藏数据、研究正文、出处文档、许可与下载内容 | 完整检查 | 检查通过后发布 |
| 未识别的输入 | 完整检查 | 检查通过后发布 |

只按明确路径识别工程文档；不把所有 Markdown 当成不发布的文件。混合改动取所需检查的并集。新模块、新引用与工程文档分类应同步更新规则和用例。

PR 明确检出最终 head 提交，使被测文件树与复用证据一致；如果合并引入新的内容，main 重新验证。PR 使用一个 `all-checks` 任务，目录检查和依赖安装各执行一次。浏览器以 `BEAMLINE_SHARD=1/1` 执行全部用例，不减少原有覆盖；不设用例过滤器。草稿跳过，转为可评审后执行，同一 PR 的新版本取消旧版本。业务步骤遵循默认的成功依赖，前一步失败后不再安装或运行后续检查。

main 可以复用刚合并 PR 的验收结果，须同时满足：

- PR 已合并到此仓库 main，合并提交就是当前 push 的终点。
- PR 来自同一仓库；最终文件树与即将发布的文件树完全一致。
- 指定 `validate.yml` 工作流已成功完成，对应同一个 PR 版本。
- `all-checks` 中目录检查和浏览器验收都实际执行成功；配置检查通过或测试跳过不算业务验收。

合并改变了内容、直接推送、fork PR、记录缺失或 API 查询失败，均回退到应执行的检查。此复用只省去同一份内容已经通过的测试；每次仍先验证当前策略和工作流。手动触发 Pages 工作流始终完整验证并发布，不复用旧结果。

PR 文件列表逐页读取并核对总数，超过 API 上限或数据不完整时运行完整检查；读取失败则阻止通过。重命名同时考虑旧路径，main 使用 push 前后的完整 Git 树比较，覆盖多提交、删除与重命名。

成功仅上传 JSON 结果，保留 3 天；失败时附带完整诊断，保留 1 天。取消后不上传证据。检查上限 15 分钟、发布上限 10 分钟。

只有实际站点发布进入 Pages 并发组，工程文档提交不会打断在途发布。正在发布的版本执行完成；若已有等待版本，新等待版本包含整个站点的最新快照。此规则适用于当前单站完整发布，不直接推广到多个独立部署目标。

本地验证：

```sh
npm ci --ignore-scripts --prefix tools/ci
npm test --prefix tools/ci
ACTIONLINT_BIN=/path/to/actionlint bash tools/ci/lint-workflows.sh
```

需要浏览器回归时，使用锁定的独立开发依赖：

```sh
npm ci --ignore-scripts --prefix tools/browser
node tools/browser/node_modules/playwright/cli.js install chromium
```

网页运行时不依赖这些开发包。完整浏览器验收仍使用 `tools/check-beamline.mjs` 原有虚构/隔离测试机制；CI 的软件渲染结果不证明真实 GPU 动画性能。
