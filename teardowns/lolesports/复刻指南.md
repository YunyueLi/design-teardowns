## 二、骨架：固定壳层加内部滚动

页面本身不滚，顶栏常驻，只有中列跟着走。

```css
main{
  display:grid;
  grid-template-rows:80px 1fr;
  grid-template-areas:"navigation" "content";
  height:100dvh;
}
.navigation{ grid-area:navigation }
.content{
  grid-area:content;
  height:calc(100dvh - 80px);
  display:grid;
  grid-template-columns:270px 1fr 320px;
}
.content > *{ overflow-y:auto }        /* 三列各自独立滚动 */

@media (max-width:768px){
  .content{ grid-template-columns:1fr }
  .content > aside{ display:none }
}
```

**用 `100dvh`，不要 `100vh`。** 移动端地址栏收起时 `100vh` 会露出空白或产生双滚动条，这是原站选 `dvh` 的原因。

## 三、签名效果一：剧透闸门

### 结构

```html
<article class="match" data-status="completed">
  <div class="match-row">
    <span class="team">…</span>
    <span class="score">2 – 1</span>
    <span class="team">…</span>
  </div>
  <footer class="match-foot">联赛 · 阶段 <span>Bo5</span></footer>

  <button class="spoiler" type="button" aria-label="显示这场比赛的比分">
    <svg><!-- 划掉的眼睛 --></svg>
    点击揭示
  </button>
</article>
```

### 样式

```css
.match{
  position:relative;                 /* 遮罩的定位基准 */
  background:var(--card-bg);
  border:1px solid var(--card-border);
  border-radius:var(--radius-control);
  overflow:hidden;
  transition:background var(--t-fast) ease-out;
}
.match:hover{ background:var(--card-hover) }

/* 两队各占一份，中间那格随状态换内容 */
.match-row{
  display:grid;
  grid-template-columns:1fr auto 1fr;
  align-items:center;
  gap:var(--space-200);
  padding:var(--space-200);
}

/* 遮罩：绝对定位覆盖，不是条件渲染 */
.spoiler{
  position:absolute; inset:0;
  display:flex; align-items:center; justify-content:center;
  gap:var(--space-200);
  background:#262626;
  color:var(--text-muted);
  font:700 14px/14px inter, Helvetica, sans-serif;
  letter-spacing:.21px;
  text-transform:uppercase;
  border:0; cursor:pointer;
  transition:background var(--t-fast) ease-out, opacity var(--t-fast) ease-out;
}
.spoiler:hover{ background:#1c1c1c }
.match[data-revealed] .spoiler{ opacity:0; pointer-events:none }
```

### 行为与偏好

原站把偏好存在 `localStorage` 的 `spoiler-protection` 键，刷新后保持（**实测**）。

```js
const KEY = 'spoiler-protection';                 // 与原站同名
const protect = localStorage.getItem(KEY) !== 'false';   // 默认开启

document.documentElement.toggleAttribute('data-spoiler-free', !protect);

document.querySelectorAll('.match .spoiler').forEach(btn => {
  btn.addEventListener('click', () => {
    btn.closest('.match').setAttribute('data-revealed', '');
  });
});
```

**默认值要设成「保护开启」。** 匿名新用户第一次进来就该被保护——等他被剧透一次再去设置里关掉，伤害已经造成了。

### 开关本身

```css
/* 开：实心填充品牌色；关：深底加描边。深色界面里实心与空心比明暗差更好认 */
.switch{ width:50px; height:30px; border-radius:20px; cursor:pointer; transition:all var(--t-fast) }
.switch[aria-checked="true"] { background:var(--brand); border:0 }
.switch[aria-checked="false"]{ background:#0f0f0f; border:2px solid #404040 }
```

用 `role="switch"` 加 `aria-checked`，不要用 `input[type=checkbox]`——屏幕阅读器会念成开关而非复选框，语义更准。这是原站的做法。

### 下拉面板

```css
.settings-panel{
  width:280px;
  background:#1c1c1c;
  border-radius:var(--radius-control);
  padding:30px 20px;
  box-shadow:rgba(0,0,0,.4) -4px 4px 4px 0;   /* 注意 X 为负 */
}
```

阴影 X 偏移取负值：面板贴视口右缘展开，阴影朝左才落在内容上，朝右会落到视口外白费。这类「锚定方向决定阴影方向」的细节，是照抄默认值做不出来的。

### 三条实现纪律

1. **别用条件渲染切换遮罩。** DOM 增删会引起卡片高度跳动，长列表里逐张揭示时观感很差。用覆盖层加透明度，揭示不触发重排。
2. **直播中的比赛不遮。** 正在打，没有结果可剧透。遮了反而让用户以为已经结束。
3. **遮罩本身要能聚焦。** 用 `button` 而非 `div`，键盘用户才能揭示。原站的类名里带 `groupFocusVisible:` 前缀，说明焦点态是显式设计过的。

## 四、签名效果二：品牌主题层

组件只认语义名，颜色由外层 `data-theme` 决定。这是同一套代码服务多个品牌的全部秘密。

```css
[data-theme="lol"]{ --brand:#10e4f9; --live:#de2f2f }
[data-theme="val"]{ --brand:#dc3030; --live:#ff4655 }
[data-theme="tft"]{ --brand:#ffb400; --live:#fb293a }
[data-theme="rb"] { --brand:#ef7d00; --surface:#fafafa; --text-primary:#0d0d0d }

/* 组件代码一行不用改 */
.live-badge{ background:var(--live); color:#fff }
.nav-link[aria-current]{ color:var(--brand) }
```

**功能语义要划出例外。** 竞猜的对错色不能跟着品牌变——原站无论切到哪个主题，判定色都固定引用同一组绿与红：

```css
:root{
  --scoring-correct:#27af75;    /* 所有主题共用 */
  --scoring-incorrect:#dc3030;
  --scoring-partial:#c79e57;
}
```

## 五、签名效果三：赛段选中态

不给条目加背景，在下面垫一层。

```css
.season{ position:relative }
.season[aria-current="true"]::before{
  content:"";
  position:absolute; inset:0; z-index:-1;
  border-left:2px solid var(--brand);
  background:linear-gradient(90deg,
    color-mix(in srgb, var(--brand) 20%, transparent) 40.5%,
    color-mix(in srgb, var(--brand) 1%,  transparent) 100%);
}
.season[aria-current="true"] .season-title{ color:var(--brand) }
```

`40.5%` 不是随手填的：渐变前四成保持满强度，文字所在区域的对比度才不被吃掉。如果改成从 0% 就衰减，标题那一行会明显发灰。

## 六、排版：一条比例关系管住所有小字

```css
/* 正字距恒为字号的 1.5% */
.label-xl{ font-size:16px; letter-spacing:.24px;  font-weight:700; line-height:16px }
.label-lg{ font-size:14px; letter-spacing:.21px;  font-weight:700; line-height:14px }
.label-md{ font-size:12px; letter-spacing:.18px;  font-weight:700; line-height:12px }
.label-sm{ font-size:11px; letter-spacing:.165px; font-weight:700; line-height:11px }

/* 标题族不加字距 */
.title-md   { font-size:18px; font-weight:700; line-height:24px }
.headline-lg{ font-size:32px; font-weight:600; line-height:40px }

/* 正文用 400，且用得极少 */
.body-md{ font-size:14px; font-weight:400; line-height:20px }
```

注意 `label` 族的行高等于字号（14px/14px）。这是给徽标、角标这类只有一行、需要紧凑盒子的元素准备的；一旦用在会折行的地方要另设行高。

## 七、选型决策

| 决策 | 原站做法 | 为什么 |
| --- | --- | --- |
| 直播播放 | iframe 嵌第三方平台 | 各赛区平台不同，自建播放器不划算 |
| 战队徽标 | PNG，286/291 懒加载 | 数量大、尺寸小，懒加载收益明显 |
| 滚动条 | 右栏用 SimpleBar | 深色窄栏里原生滚动条太丑 |
| 顶栏 | 实心，无 backdrop-filter | 广播图形语言，也省一层合成开销 |
| 动效 | 仅骨架屏扫光 | 等待是唯一无法消除的缺口，其余保持安静 |
| 圆角 | 几乎只用 4px | 保持方正，贴电竞广播气质 |
| CSS | Panda CSS 原子类 | 类名即 token 名，DevTools 可读 |

## 八、容易踩的坑

- **`100vh` 与 `100dvh`。** 应用壳层布局里这一个字母的差别，在移动端就是「底部被地址栏吃掉一截」。
- **把品牌色写进组件。** 一旦组件里出现 `#10e4f9` 字面量，多品牌就再也拆不开。只引用语义名。
- **遮罩做成条件渲染。** 见第三节。
- **`label` 族的行高等于字号。** 用在会折行的文本上会挤成一团。
- **别照抄 `--colors-red-100` 当 VALORANT 品牌色。** `#ff4655` 是它的 LIVE 与强调色；品牌表面色是 `--colors-val-red-300` = `#dc3030`。这两个值在原站是分开的，混用会让整站基调偏亮。
- **三栏独立滚动要各自处理滚动恢复。** 用户从赛程点进详情再返回，中列的滚动位置需要还原，否则长列表体验极差。原站的中列内容高 12730px，丢失位置的代价很大。
- **懒加载不要覆盖首屏。** 286/291 懒加载看起来激进，但首屏可见的那几张必须是即时加载的，否则会看到一排空位。
