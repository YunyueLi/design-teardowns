# LoL Esports 设计解构

研究对象：https://lolesports.com/en-US
抓取时间：2026 年 9 月 10 日
视口：1440×900（桌面）与 390×844（移动）
标注约定：**实锤** 指计算样式或样式表原文命中；**推断** 指观察得出，无直接证据。

---

## 一、定位：一个没有首页的产品

拆解之前先定体裁。这个仓库里以往的多数研究对象是营销落地页——一屏一个卖点，滚动即叙事。lolesports 不属于这一类。

抓取时页面标题直接是 `LoL Esports | SCHEDULE`（**实锤**）。`/en-US` 这个根路径本身就是赛程列表，前面没有品牌首页、没有 hero 视频、没有价值主张。产品团队把品牌叙事整个让给了 Riot 的其他站点，这里只保留一件事：今天有没有比赛，几点，在哪看，打完了没有。

这个定位决定了后面所有判断的角度。不该问「首屏怎么讲故事」，该问「信息密度怎么排、状态怎么区分、默认值替谁做主」。

## 二、结构：应用壳层，不是文档页

实测 `document.body.scrollHeight` 等于 `window.innerHeight`（900 = 900，**实锤**），页面本身不滚动。真正滚动的是一个高 `calc(100dvh - 80px)` 的内部容器，内容高 12730px（**实锤**）。

`main` 的实测布局（**实锤**）：

```
display: grid
grid-template-rows: 80px 1fr
grid-template-areas: "navigation" "content"
```

内容区再横分三列：

| 列 | 内容 | 滚动行为 |
| --- | --- | --- |
| 左 | 赛季导轨，七个赛段按时间纵排 | 不滚 |
| 中 | 赛程列表，按日分组 | 唯一的主滚动区 |
| 右 | 全球排名与新闻 | 独立滚动，由 SimpleBar 接管 |

移动端（390px）实测塌成单列：`grid-template-columns: 390px`、`grid-template-rows: 80px 764px`（**实锤**），两侧栏收起，中列全宽。

用 `100dvh` 而非 `100vh` 是关键（**实锤**）——移动端地址栏收起时才不会露出空白或产生双滚动条。

## 三、色彩系统：三层 token

样式表由 Panda CSS 生成，签名变量 `--made-with-panda` 留在了 `:root` 里（**实锤**）。颜色分三层声明。

### 第一层：原始调色板

命名为 `--colors-<族>-<档>`。中性色分两组，不是冗余：

- `black-1xx` 偏蓝：`#0f1519`、`#0a0e13`、`#15171a`。给整站底色。
- `black-5xx` 纯中性：`#050505`、`#0e0e0e`、`#060606`。给赛程内容区。

实测 body 背景是 `rgb(15, 21, 25)` = `#0f1519`，而赛程分组底是 `#0e0e0e`（**实锤**）。两组并存说明设计系统区分了「站点容器」与「内容容器」两个层级。

LoL 品牌色三支各四档：

| 族 | 100 | 200 | 300（主） | 400 |
| --- | --- | --- | --- | --- |
| cyan | `#a5f7ff` | `#62eefc` | `#10e4f9` | `#08becf` |
| gold | `#c5b174` | `#fdd691` | `#c79e57` | — |
| red | `#fd8a7f` | `#f64f3e` | `#ef1b06` | — |

`#10e4f9` 是品牌主色，实测出现在左栏选中态文字与右栏链接（**实锤**）。

另有七档稀有度色 `--colors-lol-rarity-*`：标准绿 `#33c252`、史诗青 `#00ddf9`、传说红 `#ff0905`、神话紫 `#d705da`、终极橙 `#fe9005`、超凡粉 `#f0bdff`、殿堂黄 `#fff58b`（**实锤**）。赛程页不用，属于奖励与藏品模块——说明这套 token 供整个站群共用。

### 第二层：品牌主题

见第六节。

### 第三层：组件语义

名字直接写组件与角色：`--colors-home-live`、`--colors-home-spoiler-text`、`--colors-home-card-hover-bg`、`--colors-home-season-overview-accent-text`（**实锤**）。复刻时应引用这一层。

实测对照表：

| 角色 | 语义 token | 实测值 |
| --- | --- | --- |
| 整站底 | `--colors-bg-primary` | `#0f1519` |
| 内容区底 | `--colors-home-bg` | `#050505` |
| 分组底 | `--colors-home-group` | `#0e0e0e` |
| 卡片底 | `--colors-home-card-bg` | `#262626` |
| 卡片描边 | `--colors-gray-500` | `#303030` |

| 剧透文案 | `--colors-home-spoiler-text` | `#a3a3a3` |

## 四、字体系统：加载三十多支，界面只跑一支

页面里有 27 个 `link rel=preload as=font`（**实锤**），`document.fonts` 报出四十余个字族名：Beaufort for LoL、Tungsten、Transducer、TT Norms Pro Compact、Riot Sans、Riot Sans 2.0 的日韩泰版本、Noto Sans 的六个文种版本、Colfax、DIN Next、Oswald、Beatrice、Cairo、Rix 系列。

但逐个量可见文本节点，结果很干脆（**实锤**）：

| 渲染字族 | 文本节点数 | 出现在哪 |
| --- | --- | --- |
| inter | 337 | 赛程页全部界面文字 |
| Inter | 15 | 右栏第三方嵌入模块（**推断**） |
| colfax | 5 | Riot 通用顶栏 |
| Helvetica | 4 | Cookie 同意条 |
| ui-sans-serif | 2 | 未命中自定义字族的兜底 |

**品牌展示体一个都没上场。** 它们属于 `display/*` 和 `headline/*` 两级排版 token，而赛程页从头到尾只用 `label/*` 和 `title/*`。功能页不需要品牌嗓门。

### 语义排版标度：五族十八档

按用途命名而非字号命名：`display`、`headline`、`title`、`label`、`body`，各自再分 xs 到 xl。同一个名字在不同品牌、不同文种下映射到不同字族，字号与行高保持不变（**实锤**）。

赛程页实际用到的几档：

| token | 字号 / 字重 | 字距 | 行高 | 用在哪 |
| --- | --- | --- | --- | --- |
| `headline/lg` | 32px / 600 | 继承 | 40px | 页面主标题、队名 |
| `title/md` | 18px / 700 | 继承 | 24px | 赛季名、日期头 |
| `label/xl` | 16px / 700 | +0.24px | 16px | 按钮 |
| `label/lg` | 14px / 700 | +0.21px | 14px | 最高频，172 处 |
| `label/md` | 12px / 700 | +0.18px | 12px | 联赛名、区域眉标 |
| `label/sm` | 11px / 700 | +0.165px | 11px | 徽标、角标 |
| `body/md` | 14px / 400 | 继承 | 20px | 正文，仅 9 处 |

`display/lg` 在 LoL 品牌下是 Beaufort 80px/900、字距 −1.6px、全大写；在 VALORANT 下换成 Transducer 58px/900（**实锤**）。赛程页用不到。

**字距的比例关系是整套排版最可复用的一处工艺**：`label` 族全部正字距，且恒为字号的 1.5%——14px 配 +0.21px、12px 配 +0.18px、11px 配 +0.165px（**实锤**）。小字在深底上加正字距是为拉开字形；`headline` 与 `title` 族字距继承（即 0），字号一大就不再需要。

字号标度共 21 档：8、10、11、12、14、16、18、20、22、24、28、32、36、40、44、46、48、52、58、64、80（**实锤**）。小字段每档只差 1 到 2px，大字段跨度拉开——典型的信息密集型产品配置。

## 五、类名即 token

Panda CSS 生成原子类，类名把 token 名写在上面。这是拆这个站最省力的一段：元素的 class 属性就是它的设计规格。

线上比赛卡的真实 class（**实锤**）：

```
bg-c_gray.506  bd-c_gray.500  bdr_4px  border-style_solid  bd-w_1px  d_block  w_100%
```

读出来是：底色 gray.506、描边色 gray.500、圆角 4px、描边 1px。计算样式核对：`#1c1c1c` / `#303030` / `4px` / `1px`，完全对上。

外层分组的 class 里还出现了 `[&:has(+section)]:bdr-b_8px`（**实锤**）——`:has()` 选择器已在生产代码里用于相邻兄弟判断。

### 间距标度

`--spacing-100` 是 8px，`--spacing-200` 是 16px，`--spacing-75` 是 6px——**token 数字除以 12.5 得像素**（**实锤**）。这种命名留出插值空间：100 和 200 之间还能塞 150，不必改名。

全套十四档：4、6、8、12、16、20、24、32、40、48、64、80、120、160。

### 圆角

定义了六档（xs 4 / sm 8 / md 12 / lg 16 / xl 24 / full 100px），赛程页几乎全用 `4px`，容器级偶尔 8px（**实锤**）。没有大圆角，没有胶囊——刻意保持方正，与电竞广播图形的气质一致。

## 六、签名系统：一个属性装下五个品牌

样式表里五个主题块并列：`[data-theme=lol]`、`[data-theme=val]`、`[data-theme=wr]`、`[data-theme=tft]`、`[data-theme=rb]`（**实锤**）。每块重定义同一组语义名，组件代码一行不用改。

| 主题 | 产品 | `surface-brand` | `live-primary` | 展示体 | 底色 |
| --- | --- | --- | --- | --- | --- |
| lol | 英雄联盟 | `#10e4f9` | `#de2f2f` | Beaufort for LoL | 深 |
| val | 无畏契约 | `#dc3030` | `#ff4655` | Transducer | 深 |
| tft | 云顶之弈 | `#ffb400` | `#fb293a` | TT Norms Pro Compact | 深 |
| wr | 激斗峡谷 | 未赋值 | 未赋值 | — | 深 |
| rb | 未确认（**推断**） | `#ef7d00` | 未赋值 | — | **浅**（`#fafafa`） |

这解释了为什么会预加载三十多支字：**这不是 LoL 赛程页的样式表，是 Riot 电竞站群共用的那一套。**

三点值得记：

1. `wr` 主题里大量语义名被赋成 `--colors-clear`（即 `#0000`，**实锤**），声明了但没配色，多半是占位或已停用。
2. `rb` 是五个里唯一的浅色主题，表面色 `#fafafa`——这套语义层从一开始就没假设「一定是深色界面」。
3. 无论切到哪个主题，`--colors-scoring-correct` 这类竞猜判定色都固定引用 val 的绿与红（**实锤**）。**对错是功能语义，不该跟着品牌变**，这个例外划得很准。

另有一处细节：`--colors-val-gold-300` 与 `--colors-lol-gold-300` 同为 `#c79e57`（**实锤**）。金色在两个品牌间共用，说明「荣誉、冠军」这类语义的配色被提到了跨品牌层。

## 七、签名交互：剧透闸门

所有体育网站的默认动作是把比分做大。这个站反过来：**比赛结束后，比分默认不显示。**

实测遮罩规格（**实锤**）：

| 属性 | 值 |
| --- | --- |
| 定位 | `position:absolute; inset:0` |
| 背景 | `#262626`（`--colors-gray-502`） |
| 文字色 | `#a3a3a3`（`--colors-home-spoiler-text`） |
| 排版 | inter 700 / 14px / 行高 14px / 字距 +0.21px / 全大写 |
| 文案 | CLICK TO REVEAL |
| 图标 | 划掉的眼睛 |

粒度分两级（**实锤**，见 `keyframes/` 与滚动截图）：有的卡只遮比分区，队名照常显示；有的整张卡遮住，队名也不给。

三态共用同一个卡片骨架，`grid-template-columns: 1fr auto 1fr`，两队各占一份，中间那格随状态变成比分、LIVE 徽标或遮罩（**实锤**）：

- **直播中**：不遮。正在打，没有结果可剧透，中间放 LIVE 徽标。
- **已结束**：遮住中间的比分区。
- **已结束且需完全保护**：整张卡遮住。

**为什么这是重要的一次判断。** 电竞观众与录播的时差很大：韩国赛区的比赛在欧美用户睡醒时早已打完。如果首页替他剧透了冠军，这个用户今天就不会去看回放了。这个默认值保护的是内容消费本身。代价是每个想快速查分的用户都要多点一下——团队把这笔账算在了看回放的人头上。

实现上用绝对定位覆盖层而非条件渲染（**实锤**）。好处是揭示时不触发重排，卡片高度稳定，一列几十张卡不会因为逐张揭示而跳动。

### 整个设置菜单里只有这一项

页面右上齿轮展开后是一个 280×90 的下拉面板，里面**只有一行**：Spoiler Protection 加一个开关（**实锤**）。没有主题、没有时区、没有通知偏好。一个只有一个设置项的菜单，比任何设计说明都更能说明团队把什么当作核心。

| 元素 | 实测规格 |
| --- | --- |
| 面板 | 280×90，底 `#1c1c1c`，圆角 4px，内距 30px 20px，阴影 `rgba(0,0,0,.4) -4px 4px 4px 0` |
| 标签 | `textStyle_label/lg`，inter 700 / 14px |
| 开关（开） | 50×30，圆角 20px，填充 `#10e4f9`，无描边，`aria-checked="true"` |
| 开关（关） | 50×30，填充 `#0f0f0f`，`2px solid #404040`，`aria-checked="false"` |
| 默认值 | 匿名用户即为开启 |
| 持久化 | `localStorage` 键 `spoiler-protection`，刷新后保持 |

三处细节：

1. **阴影向左偏**（`-4px 4px`）。面板贴视口右侧展开，阴影朝左才落在内容上，朝右会落到视口外白费。
2. **用 `role="switch"` 与 `aria-checked` 而非 `input[type=checkbox]`**（**实锤**）。屏幕阅读器会念成开关而非复选框，语义更准。
3. **关闭态换成描边式而非变灰**。开是实心填充、关是深底加 2px 描边——在深色界面里，实心与空心的差别比明暗差更容易分辨。

偏好落在 `localStorage` 而非账号上（**实锤**），换设备要重设一次。对一个不强制登录的站点这是合理取舍：匿名用户占多数，本地存储零成本且即时生效。

## 八、动效系统：几乎不做，这是配得上它的选择

整份 471 KB 样式表里只有三条 `cubic-bezier`（**实锤**）：

| 曲线 | 性格 |
| --- | --- |
| `cubic-bezier(.8, 0, 1, 1)` | 极端缓入，末段陡然加速 |
| `cubic-bezier(0, 0, .2, 1)` | 标准缓出 |
| `cubic-bezier(.215, .61, .355, 1)` | easeOutCubic |

其余过渡全用关键字。实测高频组合：`transform .2s ease-out`、`background .5s`、`opacity .5s`、`all .2s ease-in-out`（**实锤**）。时间尺度只有两档：**交互反馈 .2s，状态切换 .5s**。

自定义 `@keyframes` 六个：`spin`、`pulse`、`ping`、`bounce`、`backgroundSwipe`、`diagonalSwipe`（**实锤**）。前四个是工具类框架自带的通用动画，后两个是骨架屏扫光，跑 `1.5s linear infinite`。

**真正属于这个产品自己的动效，就是加载中的那两道扫光。** 这是对的：一个用户每天来查三次赛程的工具，动效是负担不是加分。数据要从后端拉，等待是唯一无法消除的体验缺口，扫光让等待可读；其余地方保持安静。

## 九、工艺细节

### 日期头两行同权

「星期几」与「几月几号」拆成上下两行，同为 18px/700（**实锤**）——与常见的「大日期 + 小星期」相反。原因（**推断**）：在一条只能纵向扫读的长列表里，星期几比几号更能定位「这是不是我要找的那天」，两者同权反而扫得快。

### 291 张图，286 张懒加载

首屏 DOM 里 291 个 `img`，其中 286 个带 `loading="lazy"`（**实锤**）。绝大多数是战队徽标 PNG。整页零 `video` 元素、零 `canvas`——首屏那块直播画面是 iframe 嵌入的第三方播放器（**实锤**）。Riot 把直播播放的复杂度整个外包，赛区不同则嵌不同平台。

### 右栏自定义滚动条

右侧排名与新闻列由 SimpleBar 接管，DOM 里有 `simplebar-content-wrapper`，可滚高度 787px 对 720px 视口（**实锤**）。三栏各自独立滚动是应用壳层布局必然要付的代价：原生滚动条在深色窄栏里太丑。

### 没有 backdrop-filter

顶栏实测 `backdrop-filter: none`（**实锤**）。这几年被玻璃拟态占领的顶栏，在这里是实心的。深底 + 实心 + 1px 描边，是广播图形的语言。

### 选中态是垫一层，不是加背景

左栏「当前赛段」的高亮不给条目本身加背景，而是在下面垫一层绝对定位元素（**实锤**）：

```
position: absolute; inset: 0; z-index: below
border-left: 2px solid <品牌色>
background: linear-gradient(90deg,
  rgba(16, 228, 249, .2) 40.5%,
  rgba(16, 228, 249, .01) 100%)
```

渐变在 40.5% 处才开始衰减——前四成保持满强度，保证文字所在区域的对比度不被渐变吃掉。**这个百分比是调出来的，不是默认值。**

## 十、关键发现汇总

1. 没有营销首页，根路径即产品。体裁上属于工具而非发布页。
2. 比分默认隐藏，是这个站最重要的一次设计判断，保护的是回放消费；整个设置菜单只有这一个开关，且匿名用户默认开启。
3. 一套样式表装五个电竞品牌，靠 `data-theme` 切换语义层；竞猜判定色是刻意的例外。
4. 界面字体只有 Inter 一支，品牌展示体全部缺席——功能页不用品牌嗓门。
5. 小字正字距恒为字号 1.5%，是整套排版最可复用的比例关系。
6. 间距 token 名除以 12.5 得像素，留出插值空间。
7. 动效预算全花在骨架屏上，其余保持安静。
8. Panda CSS 让类名等于设计规格，DevTools 里可直接读出决策。
