## 二、发现并已改正的漂移

| # | 漂移 | 处置 |
| --- | --- | --- |
| 1 | 方法行写「102 个 JS chunk 美化精读」 | 实际：HTML 引用 **85** 个 chunk，下载并美化 **32** 个共 30,775 行（22 个来自那 85 个，另 10 个是路由清单按需加载的 popup/drive/RendererPipeline 等）。「102」无出处，已在《设计解构》题注与《出处与方法》一、四改为 85/32/22/10 四个可复算的数字，并明说哪些没读。 |
| 2 | 《设计解构》一写「6.5 万到 26 万个彩色粒子」 | 这是**源点云**的点数（256² = 65,536、512² = 262,144）。逐份读预设的 `maxPoints` 得知实际渲染上限为 **161,001 到 629,000**——开启 `densityFill` 时会再画一遍带抖动的副本，hero 因此可达 62.9 万点。两个口径已分列。 |
| 3 | 流体参数区间四项写错 | 逐份复算 13 份预设：velocityDissipation 实为 **.96–.965**（原写 .96–.98）、densityDissipation **.9–.98**（原写 .9–.97）、pressure **.6–.9**（原写 .6–.8）、splatRadius **.25–1**（原写 .25–.5）、splatForce **.125–.5**（原写 .08–.125）、curl **1.5–6**（原写 1.5–6.56）。原区间取自部分预设，已全部改为全量极值。 |
| 4 | swipe 拱形常数写作 3.143 | 原文为 `3.1431853`，且带注释说明它必须与 knockoutShader 的 `scrollBendY` **逐字一致**，否则切边与挖空层的边会错开。这不是随手取的近似 π，而是刻意失谐的一对正弦。已在《设计解构》六与《复刻指南》二之 8 补全常数与理由。 |
| 5 | MDPC 头字段列举不全 | 实测头还含 `chromaSub: 8`（Cb/Cr 的子采样因子）、`fitBounds`（与 bbox 并存的第二组包围盒）与 `encoder: mdpc-lab.quick.shopify.io`——最后一项表明点云由 Shopify 内部工具链生成。已补。 |
| 6 | 「三支自托管字体」的文件计数含糊 | 落盘 6 个文件，但 Inter Variable 那支被两个前缀各存了一份（同一 hash `5949cd39…`），实为 **5 个不同文件**：3 个 woff2 + 2 个 ttf 兜底。已在《出处与方法》二注明。 |
| 7 | 环半径「45」未标单位与两版差异 | WebGL 版是 `radiusVmin 45`（45vmin），CSS 版是 `--hero-ring-radius: 37vmin`——两版半径不同，只有 `.35 ×` 的字号比例与 18° 倾角、102° 起始角是共用的。原文把「半径 45」与 CSS 版并列易被读成同一个值，已分列。 |
| 8 | 流场布局枚举写作「xLines / yLines / zLines / floorGrid / sphere / ripple / spokes / spiral」 | 着色器里的字符串实为九个：`off`、`dots`、`xLines`、`yLines`、`zLines`、`floorGrid`、`sphere`、`ripple`、`spokes`——漏了 `dots`，而 `spiral` 并不存在（`layoutTwist`/`layoutTurns` 两个参数容易让人以为有）。更要紧的是 13 份预设**只用到 `dots` 与 `off`**，其余七种是没启用的能力。已改。 |
| 9 | 「每个预设给 512² 与 256² 两档」 | 13 份里有 **5 份**（shopapp、marketing、agentic、merch、race-track）在两个档位填了**同一个文件**，即实际只有一档。已改为「多数预设给两档，5 份两槽同源」。 |

## 三、易错点自查

- **两组指针排斥参数并存**：hero state 里 `Ring / Animation` 带一组扁平键（strength 1、radius 1、falloff 5、damping 10、hold 131ms），`Ring / Animation / Pointer Repulse` 又带一组嵌套值（strength .08、radius 2、damping 6、hold 500ms、falloff 4）。两组数值不同且都在文件里。文档记录了这一事实并在《复刻指南》四之 10 提示复刻者先确认代码读哪一层，**未擅自判定哪组在用**。
- **`curl: 30` 是库默认，不是在用值**：FluidField 的默认对象里 curl 为 30，而 13 份预设全部覆写为 1.5–6。文档两处分开写，不可混引。
- **彩蛋未实测**：Developer 门户与 `/drive` 的跨窗 WebRTC 装置全部来自源码，本轮没有打开弹窗。《设计解构》十与《出处与方法》四均已显式声明，不写成「实测证实」。
- **KTX2 的用途是推断**：URL 与命名（`_50f_…_etc1s.ktx2`）实锤，「作为场景里的屏幕内容」是推断，级别已标。
- **`x_mj-10-pointcloud` 的 AI 来源是中置信推断**：仅凭文件名，未升格。
- **软渲染不谈手感**：tier 3 截图走 SwiftShader，只用于核验画面正确性，不用来评价帧率或流体的鼠标响应。

## 四、结论

抽样逐项与抽取源一致；九处漂移全部当场改正并在本页留痕，其中三处改变了原结论的量级或性质——JS 精读规模（102 → 85/32）、粒子数口径（源点数 vs 渲染上限）、以及流体参数区间——已同步回《设计解构》。所有推断项保留级别标注；未实测的彩蛋与未解码的 KTX2 一律不写成实锤。
