# ungetsu · 雲月 — 设计解构

对 <https://ungetsu.net/> 首页的源码级拆解。抓取时间 2026 年 9 月 11 日，
线上资源指纹与本地快照一致（`index.BKu8iCnB.css`、`index.BiYKfXdb.css`、
`GalleryEntrance…a1BdAbg9.js`），因此以下结论针对的是当前线上版本。

每条结论标注**实锤**（可回溯到抓取文件原文）或**推断**（观察与判断）。

## 一、定位与意图

这是一座个人美术馆，不是一张个人主页。

首页没有「关于我」、没有技能条、没有履历。它把五个身份——摄影、作品、文章、唱片、影像——
做成五个展厅，然后在入口处放了一轮会自己消解的月亮。必须先穿过那轮月亮，才能看到第一张照片。
这套结构取舍是全站最强的设计主张：**先给气质，再给信息**。

名字即母题。ungetsu 即「雲月」，云与月既是品牌，也是全站唯一的视觉母题：
首屏是月，页脚也是月，主题开关是月相，导航相位是月相，favicon 是月。
中间所有内容，是月亮消解后落下的尘。

**三个层次**

| 层 | 承担什么 | 手法 |
| --- | --- | --- |
| 叙事层 | 气质与门槛 | 首屏 6 084px 滚程（1440 × 900 实测），无可点内容，只有月亮被侵蚀 |
| 展陈层 | 从作品切回文档 | 粒子聚成真实照片，WebGL 把它交接给 DOM 的 `<figure>` |
| 档案层 | 信息本身 | 朴素栅格与列表，衬线、发丝线、大写水印 |

**目标读者**（推断）：会滚到底的人——同行设计师、潜在合作方，以及被一张照片留住的陌生人。
硬信息（履历、技能）全部推到二级页，首页只留三件事：拍什么、做什么、怎么找到。

**实锤**：结构化数据 `schema.org/Person` 的 `knowsAbout` 写的是
「风光摄影 / Landscape Photography / 开源软件 / AI 智能体 / 知识图谱」，四项并列无主次，
与首页把摄影和作品并排陈列的版面判断一致。站点提供 `zh-CN`、`ja`、`en` 三种语言的 `hreflang`。

**技术栈**（实锤）：Astro（含 View Transitions 与 ClientRouter）、three.js r185、
Cloudflare（beacon.min.js）。全部字体自托管于 `/fonts/`，未走第三方 CDN。

### 一个容易误读的点

词频统计里 `#000` 出现 20 次居首，但它几乎全部来自阴影 `rgba(0,0,0,x)`
与唱片的黑胶渐变，**不是品牌色**。品牌色 `--accent` 在样式表里每套主题各只声明一次。
探针的 `accentGuess` 恰好命中 `#cf5f45`，但那是巧合——它取的是深色态的计算值，
真正的依据是两个 `:root[data-theme]` 块里的显式声明。

## 三、字体系统

全站只有衬线，一个无衬线字符都没有露脸。

**实锤**：`--font-sans` 这个变量确实定义了，但整份样式表里没有任何规则消费它。
真正在跑的是三支：拉丁 **EB Garamond**、中文 **Noto Serif SC**、日文 **Noto Serif JP**，
全部自托管、全部 `font-display: swap`、全部带 `unicode-range` 分片。

### 五个字族变量

| 变量 | 声明频次 | 栈 | 用途 |
| --- | --- | --- | --- |
| `--font-serif` | 49 | EB Garamond, Noto Serif SC, Songti SC, STSong, SimSun | 正文与标题主力 |
| `--font-latin` | 15 | EB Garamond, Georgia, Times New Roman | 纯拉丁：章节标签、水印、日期 |
| `--font-meta` | 55 | EB Garamond, Noto Serif SC | 小号元信息，栈最短、回退最快 |
| `--font-ja` | 2 | EB Garamond, Noto Serif JP, Noto Serif SC, Songti SC | 日文条目 |
| `--font-mono` | 1 | ui-monospace, SFMono-Regular, Menlo… | 几乎不用，纯兜底 |

### @font-face 分布（实锤）

共 **471** 条：

| 字族 | 字重 / 字形 | 条数 |
| --- | --- | --- |
| EB Garamond | normal 400 / normal 500 / italic 400 | 7 + 7 + 7 = 21 |
| Noto Serif JP | normal 400 / normal 600 | 124 + 124 = 248 |
| Noto Serif SC | normal 400 / normal 600 | 101 + 101 = 202 |

中文 101 片、日文 124 片是 Google Fonts 的标准切法，站点把产物搬回了自己域名。
**推断**：动机大概率是首屏确定性——自托管可以与月球贴图一起排预加载优先级，
也避开第三方域名在部分网络下的抖动。

### 排版判断

- 同一支 EB Garamond 靠字距切换身份：章节标签 `.32em`、品牌字 `.28em`、正文 `.02em`。
- 中文衬线在深色底最怕发灰，解法是**标题色比正文更亮一档**（`#e8e6e0` vs `#d9d7d0`），
  并把正文行高拉到 2.0–2.2，靠留白而不是加粗立骨架。
- 日文条目标 `lang="ja"` 并切到 `--font-ja`，让日文汉字用日文字形，不被中文字形同化。
  这是全站最容易被忽略、也最见功力的一处判断。

## 四、动效系统

### 四条曲线（实锤，各只声明一次）

| 曲线 | 变量 | 用在哪 |
| --- | --- | --- |
| `cubic-bezier(.19, 1, .22, 1)` | `--ease` | 主缓动：换主题 .9s、画框换色 .9s、月相位移 .7s、卡片位移 .3s |
| `cubic-bezier(0, 0, .2, 1)` | `--ease-out` | 标准减速，给不需要「戏」的小过渡 |
| `cubic-bezier(.16, 1, .3, 1)` | — | 胶片墙落位 1.1s，每格延迟 `index × .1s` |
| `cubic-bezier(.34, 1.5, .64, 1)` | — | 唯一会过冲的曲线，只用在一处极小的微交互 |

主缓动是一条极端的 expo-out：前 20% 的时间跑完 80% 的距离，尾巴长得几乎看不见结束。
这正是「东西落到位、却不知道什么时候落的」那种高级感的来源。

### 两个时间尺度

UI 反馈 `--t-ui: .25s`，内容入场 `--t-content: .8s`。
叙事层完全不在这把尺子上——它们以秒计，甚至以滚动距离计。

| 时长 | 用在哪 |
| --- | --- |
| `.25s` | hover 变色、箭头位移、链接下划线 |
| `.26s` | 唱头落针 |
| `.3s` | 导航圆点缩放、唱片封面抬起 |
| `.4s / .45s` | 页面切换 `vt-lift` / `vt-settle` |
| `.7s` | 主题图标月相移动 |
| `.8s` | 内容入场、唱臂摆动（延迟 `.24s`） |
| `.9s` | 换主题时底色与画框边色同步过渡 |
| `1.1s` | 胶片墙每格落位 |
| `1.15s` | 单个汉字点亮 |
| `1.8s` | 宽幅照片交叉淡入 |
| `2.4s` | 主题按钮 hover 流光环 `arc-flow`（infinite linear） |
| `4.6s` | 黑胶转一圈 `m-spin`（约 13 rpm，慢于 33⅓ 的写意值） |
| `6.4s` | 落款书写一遍 |
| `7s` | 宽幅照片轮播间隔 |

### 逐字点亮的节拍（实锤）

来自 `home-late-motion.CO2yWLHu.js`：

- 每字步进 **26ms**；遇到 `，。！？` 步进加到 **105ms**；段与段之间再加 **300ms**
- 单字动画 **1150ms**，缓动 `cubic-bezier(.22, .61, .36, 1)`
- 起始态 `opacity .16 / translateY(.16em)` → 终止态 `opacity 1 / translateY(0)`
- 触发 `IntersectionObserver`，`rootMargin: 0px 0px -16% 0px`
- `prefers-reduced-motion` 下直接跳到完成态
- 原文被拆成两份：一份 `music-poetry-spoken` 视觉隐藏但可被读屏读到，
  一份 `music-verse` 逐字动画且 `aria-hidden` ——**动画不牺牲可读性**

标点停顿这一条，是把中文的呼吸写进了代码。

## 五、Hero 手法与签名母题

### 母题一：月相消解

月亮不是视频，也不是序列帧，是 three.js 里的一颗球配一支自写 `ShaderMaterial`，
外加一整套 GPU 粒子。消解不靠透明度渐隐，靠一条「侵蚀锋面」扫过球面。

`moon-material.D6ghfIzk.js` 原文：

```glsl
float lunarFront(vec3 localPoint,float albedo){
  return .5+(localPoint.x*.927+localPoint.y*.375)*.35+(albedo-.6)*.22;
}
float lunarErosion(float progress){
  return smoothstep(.27,.70,progress)*1.45-.2;
}
float lunarRelease(vec3 localPoint,float albedo,float progress){
  float front=lunarFront(localPoint,albedo);
  return smoothstep(front-.16,front+.16,lunarErosion(progress));
}
```

三行能读出三件事：

1. `(x*.927 + y*.375)` 是固定方向向量——侵蚀有方向，从左下往右上推。
2. `(albedo-.6)*.22` 让**月海先放走、高地后放走**：暗处 albedo 低，front 更小，更早被锋面越过。
3. `smoothstep(front-.16, front+.16, …)` 给锋面 0.32 宽的软带，边缘因此是砂砾状而非刀切。

**实锤**：侵蚀进度不等于滚动进度。滚动 0→1 只把 `uProgress` 从 `.45` 推到 `.7`
（`lerp(.45, .7, min(1, p/.7)²)`），且月亮在 `p > .72` 时整颗隐藏，剩下交给粒子。
**推断**：让「实体」与「尘」的交接发生在注意力最松的一段，交接痕迹因此看不见。

月面着色（**实锤**）：水墨三色 `uPaper / uLightInk / uDarkInk`；
法线贴图只在明暗界线附近扰动一条窄带（`exp(-abs(sun)*14.)`），
保证月球始终只有一条连续轮廓，而环形山边缘能接到掠射光。

### 尘的三段旅程（实锤，`lunar-scene.Cpz5gDLB.js`）

1. **起皮 peel** — 先沿法线离开球面 `r × .045 × lift`，同时加一个 `sin(lift·π)` 的切向摆动，
   像颜料从纸上翘边。
2. **入流 stream** — 汇进 `lunarStream()`：一条 `sin(x·7.1 + lane·.19 + t·.016)` 的带状流，
   按 `lane` 分五道，z 向深度 210。这就是首屏那条横贯画面的银河。
3. **落位 arrival** — 按 `photoArrival(uv, progress)` 归位到照片像素，
   路径带 `sin(b·π)(1-b)` 的弧形包络，两端为零，所以反向滚动依然平滑。

另有 `step(.995, seed.z)` 约 0.5% 的粒子被标成 free，永远不参与落位，只做环境尘。
横向漂移用 `fract(seed.z + t*.055)` 做周期重置，并在 wind 的首尾用
`smoothstep(0,.08,wind)*(1-smoothstep(.85,1,wind))` 把透明度压到零——**重置那一帧看不见**。

### 规模（实锤）

| 参数 | 桌面 | 移动 |
| --- | --- | --- |
| 粒子数 | `480 × 360 = 172 800` | `240 × 180 = 43 200` |
| 球体分段 | `256 × 192` | `160 × 112` |
| 月球贴图 | 4096 webp | 2048 jpg / png |
| 云 raymarch 步数 | 44 | 28 |
| 云层数 | 3（各占一个 render layer） | 同 |
| 云渲染目标 | `HalfFloat`，视口 0.65 倍，预乘还原后合成 | 同 |
| 3D 噪声 | `64³`，八度 4 / 8 / 16，权重 `.57 / .28 / .15`，模块级缓存 | 同 |
| 像素比上限 | `min(dpr, 1.75)` | `min(dpr, 1.25)` |
| 随机源 | LCG 种子 `21717`，乘子 `1664525`，增量 `1013904223` | 同 |
| 点尺寸 | `clamp(.7, 12)` | 同 |

**推断**：种子写死而不是 `Math.random()`，说明作者要的是每次刷新完全一致的画面——
这是把网页当作品而不是当应用的标志。

### 母题二：落款书写

首屏 `<h1>` 是一段 `529 × 205` 的 SVG，`aria-label="雲月 Ungetsu"` 兜住语义。
笔迹是矢量路径，做动画的是一张 PNG：`/scene/signature-arrival.png`
的 alpha 通道里烧着**书写顺序**——先写的地方 alpha 小，后写的地方 alpha 大。

```html
<filter id="signature-writing-hero-threshold" color-interpolation-filters="sRGB">
  <feComponentTransfer>
    <feFuncA type="linear" slope="-90" intercept="10.9265625"/>
  </feComponentTransfer>
</filter>
```

解式子：`a' = -90a + intercept`。当 `intercept = 90p` 时，
`a' ≥ 1` 的条件是 `a ≤ p - 1/90`，`a' ≤ 0` 的条件是 `a ≥ p`。也就是——
**斜率 -90 = 一条宽度 1/90 的软边笔锋，intercept ÷ 90 = 笔尖当前位置**。

抓到页面时 `intercept = 10.9265625`，除以 90 得 `0.12140…`，
与 DOM 上的 `data-ink-progress="0.121"` 对得上；`data-duration="6400"` 即写完一遍 6.4 秒。

**推断**：高明之处在于它用**一张位图 + 一个滤镜**解决了「中文笔顺动画」这个
SVG `stroke-dashoffset` 根本做不了的问题——行书的连笔、飞白、粗细变化，dash 方案全部无能为力。

页脚还有第二个落款，透明度压到 `.16` 当水印，外套 `radial-gradient` 把中心擦出来；
上面盖一个 `.sig-gate` 全尺寸按钮——长按让水印从 `.16` 升到 `.5`（`.78s linear`），
随后触发 `vault-veil` 白场进入一个未公开页面。**推断**：刻意留的彩蛋入口，
金色 `--gold` 这个变量全站也只服务它。

`<noscript>` 里写着 `.signature-ink{mask:none!important}`，
`prefers-reduced-motion` 下同样去掉遮罩——**没有 JS、不要动画的人，直接看到写完的字**。

### 母题三：照片显影

交叉淡入的老毛病是中途出现两张半透明照片叠印。站点在着色器注释里直接写了这件事，
并用一条细粒度曝光锋面解决：

```glsl
float field   = vUv.x*.60 + vUv.y*.20 + formationNoise(vUv*4.)*.20;
float front   = smoothstep(.08,.82,uExit)*1.24 - .12;
float grain   = formationHash(floor(vUv*vec2(2200.,1800.))) - .5;
float arrival = smoothstep(-.008,.008, front - field + grain*.038);
vec3  color   = mix(previous, next, arrival);
color *= 1. - sin(uExit*3.14159265)*(.014*(1.-vUv.y));
```

- `field` 决定扫过方向：x 权重 .60 大于 y 的 .20，是一条略倾斜、偏水平的锋面
- `formationNoise` 让锋面不是直线，带 20% 低频起伏
- `grain` 按 `2200 × 1800` 像素格产生高频颗粒，振幅 `.038`——银盐颗粒感就来自这里
- `smoothstep(-.008, .008, …)` 过渡带只有 0.016 宽：**锋面是硬的，颗粒是软的**，永不叠影
- 最后一行压了一点底部亮度，换片中途整张照片极轻微地暗一下，像相纸入液

粒子落位用另一支函数，让照片从中心偏右上 `(.56, .55)` 向外圈显影，且每颗时长不同：

```glsl
float photoArrival(vec2 uv,float progress){
  vec2 q = (uv-vec2(.56,.55))*vec2(1.,1.25);
  float order = clamp(.15+length(q)*.92+(formationNoise(uv*4.2)-.5)*.42,0.,1.);
  float t = clamp((progress-(.42+order*.13))/(.37+order*.03),0.,1.);
  return t*t*t*(t*(t*6.-15.)+10.);   // smootherstep
}
```

`vec2(1., 1.25)` 把圆形显影波压成椭圆贴合横构图；`order*.13` 是延迟、`order*.03` 是时长，
外圈既来得晚、落得也更慢；末尾的 smootherstep 二阶导在两端为零，反向滚动不会弹回。
**全站的滚动映射用的都是 smootherstep，不是常见的 smoothstep。**

## 六、滚动编排

### 首屏高度（实锤，页面内联 `<style>`）

### 阶段（实锤，写在 `data-phase` 上）

| 阶段 | 条件 | 画面 |
| --- | --- | --- |

`--ge-handoff` 在 `p > .96` 打开，`--ge-wide-opacity = smootherstep((p-.96)/.04)`。

### 四个值得偷的做法

**1｜驻留是解出来的，不是等出来的**
「月亮停一下」不是 `setTimeout`，而是把驻留距离塞进滚动映射函数：
用 20 次二分求解一个带 smootherstep 平台的反函数。
好处是**正反向滚动完全对称**，往回滚也会在同一处停住。

**2｜滚动值要过一道阻尼**
渲染读的不是 `scrollY`，是一个跟随它的弹簧：`v += (target - v)(1 - e^(-dt·U))`，
常态 `U = 3`、退场段 `U = 5`；差值小于 `.05` 直接吸附。触控板的高频抖动因此被吃掉。
另有一条「地板」：`v = max(v, morph × smoothstep((s-morph)/holdFloorSpan))`，
防止快速回滚时画面倒退过头。

**3｜rAF 是按需的**
没有常驻 `requestAnimationFrame` 循环。只有滚动、指针移动、resize 才排一帧；
画面稳定后自动停摆。`IntersectionObserver` 移出视口即取消，`dialog[open]` 打开也停，
`visibilitychange` 隐藏也停。

**4｜指针会让画面呼吸**
鼠标在首屏移动时相机跟着偏移：系数 `12` 与 `9`，指针归一化到 `±0.5`，
即实际 `±6px / ±4.5px`；再乘以 `1 - smoothstep((p-.72)/.26)`——
**越接近交接，视差越弱**，免得照片落位时还在晃。仅在 `(pointer:fine)` 下启用。

### 交接那一帧（实锤）

退场段真正做的事，是把 WebGL 里那块照片平面飞到 DOM 里 `<figure> img` 的实际屏幕位置：
脚本每帧读 `getBoundingClientRect()`，把矩形写进 `THREE.Vector4`，
再用 smootherstep 插值位置与尺寸。飞行途中平面还有一个
`sin(uv.y·π)·sin(uExit·π)·height·.022` 的微弓——照片像一张相纸那样轻轻卷一下再摊平。

同时一串 CSS 变量被写出来驱动 DOM 侧：

| 变量 | 公式 | 作用 |
| --- | --- | --- |
| `--ge-exit-caption` | `1 - smootherstep(p/.14)` | 旧说明淡出 |
| `--ge-plate-opacity` | `p === 1 ? 1 : 0` | 到 1.0 才让 DOM 图显形，避免两张图同时可见 |
| `--ge-framing-opacity` | `smootherstep((p-.68)/.3)` | 标签与胶片条比正文晚到 |
| 故事文案 | 起点 `[.59,.64,.69,.73,.77]`，各跨 `.23`，位移 24px | 五个子元素错峰入场 |
| `section.inert` | `p < .94` | 没落位就不给焦点 |

### 相机（实锤）

FOV 38、距离 `height / (2·tan 19°)`。相机不平移场景，而是场景按视口尺寸铺开，
所以布局在任何窗口比例下都保持同一构图。

### 玻璃镇盘器：它是真的在光追

压在唱片中央的玻璃棱锥不是贴图、不是折射近似，是一个**自带 BVH 的屏幕空间光追 pass**。
模块里打包了完整的 `three-mesh-bvh` GLSL——`intersectsBounds`、`usampler2D` 存的 BVH 节点、
三角求交——在片元着色器里对着它自己的几何求交：

```js
this.bvh.updateFrom(new MeshBVH(geometry, { targetLeafSize: 4 }));
this.material = new ShaderMaterial({ uniforms: {
  bvh, colorBuffer, depthBuffer, environment, hasEnvironment,
  environmentIntensity: .5, worldToLocal, worldNormal,
  cameraView, cameraProjection, inverseProjection, environmentRotation
}});
```

它拿到上一趟渲染的**颜色缓冲与深度缓冲**，让光线在玻璃内部真实地折、反、再折出去——
所以棱锥里能看见被压扁、倒置、错位的唱片与背景，而不是一团糊的高斯模糊。

**三种玻璃，三套参数**

| 用处 | ior | thickness | roughness | 衰减色 / 距离 |
| --- | --- | --- | --- | --- |
| 镇盘棱锥 | 1.52 | `.59` | `.003` | 纯白（不吃色） |
| 转盘玻璃 | 1.52 | `.1` | `.007` | `#c8e6e1` / `8` |
| 唱臂亚克力 | 1.49 | `.055` | `.025` | `#ecf5f5` / `1.6` |

棱锥的形是手写的：一个八点轮廓（四角按 `min(.005, 半宽×.3)` 倒角），沿 `y` 依次取
`.292/0 → .295/.003 → .295/.078 → .292/.084 → .006/.71 → .004/.72` 六层，
最后收到顶点 `(0, .72, 0)`；底面挖半径 `.037` 的轴孔。
每个三角还做退化剔除（叉积模长 `< 1e-16` 直接丢）——
**推断**：退化三角会让 BVH 求交出脏点。

### 彩虹不是贴图，是六盏灯

发光面是一块 `64 × 24` 细分的四边形，材质带 `emissiveMap`、`emissiveIntensity 2.3`；
UV 不是线性铺的，而是先求一个**单应矩阵**再做透视除法 `(P.x/P.z, P.y/P.z)`，
所以光带在斜面上不会被拉歪。

真正让它「照亮房间」的是另一半：沿同一块四边形**等分排了六盏矩形面光**，
强度 `1.5`、高 `.11`，颜色正是光谱六色
`#7049ad`、`#248cd0`、`#329835`、`#ffce13`、`#ff7a08`、`#e52b0d`。
每盏按那条边的实际长度设宽、按端点连线方向 `rotateZ` 对齐。
**所以彩虹会真的在黑胶上留下六道有颜色的反光**——不是后期叠色，是物理光照。

### 黑胶材质：各向异性 + 三张唱纹贴图

```js
new MeshPhysicalMaterial({
  color: 0x08090b, roughness: .82, ior: 1.54,
  anisotropy: .65,  anisotropyMap:  grooveDirection,   // 唱纹方向图
  roughnessMap:    grooveRoughness,                    // 唱纹粗糙度图
  normalMap:       grooves, normalScale: new Vector2(.6, .6),
  envMapIntensity: .6, specularIntensity: .75,
  clearcoat: .08, clearcoatRoughness: .24
})
```

三张贴图各司其职：`grooves` 给法线细节、`grooveRoughness` 让沟底与沟脊粗糙度不同、
`grooveDirection` 告诉引擎**每一点的唱纹朝哪个方向**——各向异性高光就沿这个方向拉开。
加上 `clearcoat .08` 那层薄清漆，黑胶才有「表面一层、纹理一层」的双层反光。
唱片本体 `Cylinder(1.498, 1.498, .02, 256)` 加上下两片 `Circle(1.498, 256)`，
标签 `Circle(.49, 128)`。

### 唱臂角度：解三角形，不是插值

整台机器最硬的一处。唱臂不按播放进度线性转，而是**按唱针应该落在的半径反解出臂的角度**——
标准的余弦定理：

```js
// 常量：主轴 (-.85, 0, .62)　臂枢轴 (.93, 0, -.292)　有效臂长 2.185
function armAngle(progress){
  const r = 1.44 - clamp(progress, 0, 1) * .85;   // 落针半径：外圈 1.44 → 内圈 .59
  const d = pivot.clone().sub(spindle);
  const n = Math.hypot(d.x, d.z);                 // 主轴到枢轴的距离
  return Math.atan2(d.x, d.z)
       - Math.acos(clamp((r*r - n*n - L*L) / (2*n*L), -1, 1));
}
```

三角形的三条边是：主轴到枢轴（固定）、臂长 `2.185`（固定）、唱针到主轴的半径（随进度变）。
解出夹角就是臂该转到的角度。**唱针在唱片上的落点是几何正确的**——
不是「看起来在往里走」，是真的在正确的半径上。
**推断**：会这么写的人，多半自己拧过唱臂。

**唱臂上还有什么**：轴承座四层圆柱、可拆唱头壳（`Shape` 挖 `.093` 圆孔后
`ExtrudeGeometry` 带 5 段倒角）、配重、抬臂杆、防滑锤（`12` 圈螺旋线扫成管，管径 `.0015`）、
循迹力刻度盘（**256² canvas 现画**刻度数字与三格刻度条，贴到 `Circle(.054, 48)`）、
唱针（半径 `.003` 的球）。最见细节的是**四根唱头接线**——
四条 `CatmullRom` 扫成的细管，管径 `.002`，颜色 `#713e32`、`#344958`、`#315448`、`#afa697`，
末端各带一个金属插针。**四根线，四种颜色，和真唱头一模一样。**

### 镜头推轨：两条 centripetal 样条

那 690svh 的推近不是插值位置，是**两条曲线同时走**：一条给相机位置（5 个控制点），
一条给注视点（5 个控制点），都用 `CatmullRomCurve3(..., false, "centripetal")`——
**推断**：选 centripetal 参数化是因为它不会自交、不会甩尾，控制点疏密不均时轨迹依然平顺。
相机是 `PerspectiveCamera(31, 1, .04, 150)`，FOV 31 比首屏月景的 38 更长焦，
压缩透视，物件看着更「贵」。

结束位的取景距离是**算出来的**：取视轴 `normalize(.2, .83, 1)`，把包围盒八个角投影上去，
按水平与垂直两个视锥半角分别求所需距离，取最大再乘 `1.02`。
**所以任何窗口比例下整台唱机都刚好装得下、又不空。**
窄屏则把曲线端点整体外推 `1.4` 倍（其中一个点 `1.25`），把镜头拉远。

### 这台机器的预算

| 项 | 值 | 说明 |
| --- | --- | --- |
| 渲染像素预算 | `min( max(2, dpr), √(5 000 000 / 屏幕像素) )` | **总渲染像素封顶 500 万** |
| 后处理 | `EffectComposer` + `HalfFloat` RT，`samples: 4` | 4× MSAA，另挂输出 pass 与 FXAA pass |
| 色调映射 | 曝光 `.9` | 比简版的 `.86` 稍亮 |
| 阴影 | PCF（`PCFShadowMap`），`1024²`，`autoUpdate = false` | 只在尺寸变化时手动更新一次 |
| 阴影相机 | 正交 `±4`，`near .1 / far 14`，`normalBias .009`，`bias -1e-4` | 贴着场景收紧，换分辨率 |
| 主光 | 3 盏矩形面光：`#f5f8ff` 7、`#dbeaf9` 9、`#fff4e5` 2.5 | 两冷一暖，各自 `lookAt` 不同焦点 |
| 定向光 | `#f0f4ff`，强度 `.5`，投影 | 只负责那道硬阴影 |
| 地面 | `Plane(200, 200)`，`#121615`，粗糙度 `.46` | 接住反射与阴影 |
| 预加载 | `rootMargin: 1200px` | 提前 1200px 就开始拉模块 |
| 背景雾 | 另起一个 `low-power` 渲染器跑一层噪声 | 灯光场与主场景分开 |

**推断**：「总像素封顶 500 万」比常见的 `min(dpr, 2)` 讲究得多——
它约束的是**实际要着色的像素总数**，而不是设备像素比这个间接量。
4K 屏上自动把像素比压到 1 出头，小窗口里又允许上到 2：**预算恒定，画质自适应**。

### 简版唱机（唱片架页）

作为对照，`/music` 那台 8.6KB 的简版取舍完全不同：
`powerPreference: "low-power"`、`ACESFilmic` 曝光 `.86`、像素比封顶 `1.65`、
相机 FOV 34 固定在 `(.25, 5.9, 5.5)`；环境反射来自代码里手搭的一间「房」——
一盏 `PointLight(0xffffff, 900, 28, 2)` 加六块发光面板（`emissiveIntensity`
`50 / 50 / 17 / 43 / 20 / 100`），`PMREMGenerator.fromScene(room, .025)` 烘完
**房间当场 `dispose()`**，只留贴图。另有两盏方向光：暖白 `#fffcf6` 强度 `2.4`、
冷白 `#e9eef2` 强度 `1.7`，加 `0.25` 环境光。

整台机器只有三种材质：金属 `#55595b`（metalness `.86` / roughness `.38`）、
琴箱 `#090a0b`（`.12` / `.58`，`envMapIntensity .18`）、哑光 `#080809`（`.08` / `.58`）。
唱臂是一条穿过四点的 `CatmullRomCurve3` 扫成的 `TubeGeometry(40, .026, 12)`。
唱纹靠一支十行着色器假装：径向方向与固定光向 `(-.72, -.44)` 点乘取 **22 次方**
得到一道窄高光，再让唱纹调制它（`sheen * (.018 + grooves*.16)`）。
唱纹本身是**真的一圈一圈画**的：半径 `.52` 起步进 `.0088`，共 94 圈，每圈 160 段线，
跳过第 31、32、65 圈做分轨间隙。

转速是**真实的 33⅓**（`Math.PI × 2 × 33.333 / 60`），用 `MathUtils.damp` 阻尼：
转速 λ `3.3`、换片抬起 λ `13` 升 / `8` 落（`y = .42`，同时 `rotation.z = y × -.17`）、
唱臂角 λ `4.5`（`-.42 - 进度 × .19`）、唱头俯仰 λ `9`（到位判据 `|Δ| < .045`）、
指针视差 λ `5`。限帧 30fps，空闲 `1800ms` 后停摆。

**两台机器的分工很清楚**：首页那台是「作品」，唱片架那台是「工具」。
同一个母题，两种预算，各自把该省的省掉。

DOM 版唱机的关键数值（**实锤**）：转盘 `m-spin 4.6s linear`；
唱臂 `rotate(26deg) → rotate(7deg)`，`.8s var(--ease)`，**落针延迟 `.24s`、抬臂无延迟**；
唱臂 `transform-origin: 50% 13px` 正好落在配重轴心；唱头 `.26s` 单独过渡。

### 性能取舍（实锤）

- 首屏关键路径只预加载四个模块：`mini-lunar`、`three.module`、`moon-material`、`moon-phases`
- 月球贴图按 `innerWidth < 701` 二选一
- `EXT_color_buffer_float` 不可用时，云层退回「三层一起画」的简化路径而不是报错
- `webglcontextlost` 有监听，丢上下文即整体降级为静态图
- `astro:before-swap` 上统一 dispose：几何、材质、纹理、渲染目标、`forceContextLoss()`

## 九、关键发现（一句话版）

1. **一个母题，五处出现，其余零装饰。** 月亮在首屏、页脚、主题开关、导航相位、favicon 上。
2. **消解是一条有方向、认亮度的锋面**，不是透明度渐隐——`(albedo-.6)*.22` 让月海先走。
3. **换图用硬锋面 + 软颗粒**，`smoothstep(-.008,.008,…)` 配 `grain*.038`，永不叠影。
4. **中文笔顺动画用位图顺序 + 一个滤镜解决**，`slope=-90` 就是 1/90 宽的笔锋。
5. **驻留塞进滚动映射函数**，用二分求反函数，保证正反向对称。
6. **滚动值要过指数阻尼**，`U = 3 / 5`，差值 `.05` 吸附。
7. **rAF 按需排帧**，稳定即停摆；出视口、开弹窗、切后台全停。
8. **UI 色与场景色分层命名**，场景明暗靠读底色亮度而不是主题名。
9. **标点停顿写进逐字节拍**（26ms / 105ms / 300ms），中文的呼吸被编码了。
10. **每一步都有 B 计划**：无 WebGL、无浮点纹理、无 JS、不要动画，各有一条完整路径。
