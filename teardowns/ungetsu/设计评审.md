# ungetsu · 雲月 — 设计评审

以顶级设计视角评审两件事：**原站的设计**，以及**本拆解的精度与完成度**。

---

## 一、原站评审

### 一句话

这是一份把工程能力当表现材料用的设计。

大多数个人站的天花板是「审美不错」。这一个越过了那条线，原因不在品味，在**公式**：
侵蚀锋面里的 `(albedo-.6)*.22`、显影颗粒的 `.038`、标点停顿的 `105ms`、落针延迟的 `.24s`——
这些数不是调参调出来的，是先想清楚了物理与感受之间的关系，再写下去的。

### 做得最好的三件事

**一｜母题极度克制。**
月亮只此一个，出现在首屏、页脚、主题开关、导航相位、favicon 五处，其余零装饰。
个人站最常见的失败是「每一节都有一个新效果」，这里反过来：**一个效果，贯穿到底**。
`--gold` 这个变量全站只服务一个隐藏入口，`cubic-bezier(.34,1.5,.64,1)` 只用在一处微交互——
克制到这种程度，母题才立得住。

**二｜降级路径完整到罕见。**
WebGL 挂了有静态图；浮点纹理不支持有简化 raymarch 路径；三维唱机挂了有整套 DOM 唱机；
没有 JS 也能看到写完的落款；`prefers-reduced-motion` 下每个动画都有明确的完成态。
这不是补丁，是从一开始就按「这段可能跑不起来」写的。

**三｜无障碍不是事后补的。**
`inert` 跟着动画进度走（`progress < .94` 就不给焦点）、
自动轮播可暂停且同步改写 `aria-label`、canvas 有中文 `aria-label` 而不是空 alt、
逐字动画拆成「可读版 + 动画版」两份。最后这一条尤其少见——
绝大多数逐字效果都会让读屏逐字念出来。

### 可以更好的三件事

**一｜首屏成本对新访客是笔重税。**
1440 × 900 下要滚 6 084px 才见到第一张照片；期间加载 three.js、4K 月球贴图、
172 800 个粒子。目前唯一的快捷键是「进入展览」按钮（一段 1.4–4.2s 的程序化滚动），
但它在版面里的视觉权重明显低于那轮月亮。
**可执行改进**：把「进入展览」提到与题词同一视觉层级，或在首次访问 8 秒后浮出一次提示。

**二｜叙事层与档案层之间落差偏大。**
过了首屏，作品与文章两节回到很朴素的列表；唱片厅又忽然拉回 690svh 的三维推轨。
节奏是「极浓 → 极淡 → 极浓 → 淡」，中间那次落差来得有点突然。
**推断**这可能是刻意的对照，但对照缺一个过渡件。
**可执行改进**：给文章节一个轻量的母题回响（例如列表 hover 时泛起一道极淡的尘），
成本极低，能把两层缝上。

**三｜静态抓取下大面积空屏。**
整页文档高 16 035px，其中 6 084px 在不滚动时是纯黑。
这对搜索引擎的视觉预览、社交分享的自动截图、以及任何「先扫一眼」的场景都不友好。
**可执行改进**：给 `.ge-stage` 一个 `@media print` 与「无滚动上下文」时的静态兜底构图
（月亮 + 落款 + 一张照片），成本低于十行 CSS。

### 一句话总结

它把一轮月亮的消解写成了一个可复现的函数，然后把这个函数当成了首页。
值得学的地方，几乎全在那几行公式里。

## 二、本拆解评审

### 达标在哪

- **公式层面做到了源码级**。三段签名效果（月相消解、落款书写、照片显影）
  都不是「看起来像」，而是把线上着色器与滤镜参数逐字取回并可交互重放。
- **分段距离是量出来的，不是算出来的**。四种视口下读 DOM 的 data 属性，
  比从 `clamp()` 心算可靠——事实核查里第 1、2 条漂移正是这一步抓出来的。
- **真字体真接入**。122 条 `@font-face` 由站点原文改写本地路径生成，
  `unicode-range` 分片与权重保持原样，中文样张用的是真的 Noto Serif SC。
- **拆解页说的是被拆对象的语言**。画框、印章、月相开关、章节水印、幕布页脚、
  双主题翻转，全部照抄真实构造；页面自身也用 `cubic-bezier(.19,1,.22,1)` 运动。
- **实锤与推断逐条分离**，且推断都给了理由，没有把猜测写成事实。

### 相对原站还差在哪

| 差距 | 说明 |
| --- | --- |
| 三个 demo 是 Canvas 2D 重写 | 月面逐像素重建、尘 9 000 点（原站 172 800）、无体积云、无相机视差。**公式与素材是真的，体量与精度不是** |
| 唱机只复刻了 DOM 版 | 两台三维唱机都已逐值拆到文档里，但拆解页没有重建可跑的三维版——重建需要 three.js 加 BVH 光追，与「拆解页要能在任何设备上打开」冲突 |
| 首屏编排用进度条代替 | 体裁不同：拆解页是文档，不能也不该把 6 000px 的滚程照搬进来 |
| 未进入隐藏页 | 页脚长按彩蛋通向的页面未拆 |
| 滚动到样条参数的逐帧插值未展开 | 两条镜头样条的控制点与取景算法已拆，滚动如何映射到样条参数这一小段未逐行读 |
| 只拆中文首页 | 二级页与 ja / en 版本未做对照 |

以上均已在页内与 [出处与方法.md](出处与方法.md) 就地注明，不是隐藏的短板。

### 本轮已当场修掉的问题

1. 首屏滚程从心算的「8 700px」改为实测 6 084px，并补四视口实测表。
2. 轨道图把「驻留」从独立分段改画为变形段内部的平台，并把带平台的映射函数照搬进 demo。
3. 指针视差从「±12px / ±9px」改正为「系数 12 / 9，实际 ±6px / ±4.5px」。
4. 字节数与字符数、设备像素与 CSS 像素两处口径串台已分开标注。
5. 色板色块加了一道内发丝线——深色值在深底上原本几乎看不见，
   忠实于原站但不利于阅读，这是拆解页该做的取舍。
6. 幕布底图改用站点真实的双主题混合模式（浅 `multiply .6` / 深 `screen + invert(1) .5`），
   此前直接铺图导致深色态下整块发白。
7. 月亮 demo 的自动巡航区间收到 `.36–.78`——全量 0–1 里有大半区段画面不动，
   拖着像坏了。
8. **补拆了简版三维唱机**。第一轮只读了 CSS 布局与降级路径就收工，
   漏掉了 `spatial-deck.C_Ps8k2h.js` 模块本身。
9. **拆错了唱机，第三轮才改对**。补拆时又只看到 `spatial-deck`，
   没注意 `MusicDeck` 其实按 `data-spatial-deck` 分流到两个模块——
   首页那台是 `music-chapter.Bm7fAGSv.js`，**363KB**，
   里面是 BVH 屏幕空间光追的玻璃镇盘器、六盏彩虹矩形面光、
   带三张唱纹贴图的各向异性黑胶、用余弦定理反解的唱臂角度、
   以及两条 centripetal 样条做的镜头推轨。
   **这是全站技术密度最高的一段，前两轮都漏了。**
   教训：看到一个模块能解释现象，不等于它就是当前页面在跑的那个——
   得先把分流条件读清楚。

### 还可以更进一步（未做，成本与收益说明）

- **重建一台可跑的三维唱机**：几何、材质、灯阵数值都齐了，但拆解页只放了 DOM 版；
  还原电影版需要 three.js 加 BVH 光追，与「拆解页必须在任何设备上都能打开」冲突。
- **把光追玻璃单独做成 demo**：屏幕空间 BVH 折射这一套是可以脱离唱机复用的通用技术，
  值得单独成篇。
- **拆二级页**：`/photos/` 的展览页与 `/music/` 的唱片架大概率有独立的编排逻辑，
  值得单独成篇而不是塞进本页。
- **给 demo 加 WebGL 版**：能把粒子体量拉到接近原站，但会引入 three.js 依赖，
  与「拆解页必须在任何设备上都能打开」冲突——**此处选择了兼容性**。
